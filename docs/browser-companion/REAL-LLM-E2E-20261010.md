# Switchboard CLI → real AI model → background Chrome extension → answer

**Verified:** 10 October 2026 (WIB)
**Device:** Windows laptop `home`
**Branch:** `feat/chrome-browser-companion`
**Verdict:** **PASS — two independent real-provider E2E runs**

## Architecture exercised

```
User prompt in Switchboard CLI
  → BotConnector API (real authenticated provider)
  → Agnes 3.0 Flash model selects browser_* tools
  → Switchboard local authenticated WebSocket bridge
  → Manifest V3 Chrome extension service worker
  → Actual Chrome for Testing 154 tab, localhost test page
  → Browser results returned to the Switchboard agent
  → Model returns an Indonesian answer citing observed result
```

The browser extension's panel was **closed before the prompt was submitted and remained closed**. No mock model, fake tool result, or CDP-assisted click was used. CDP was used separately to reset the test counter **before** the model run and independently verify it **after** the model finished.

## Constraints

- **Verified:** local `sbx chat --preset browser --yes` with a real provider, background extension and real Chrome tab.
- **Not verified here:** standalone Web UI bridge parity, Microsoft Edge live browser test, Chrome Web Store submission, public installation onboarding, long-running multi-user load.
- Chrome screenshot capture still needs Chrome's separate `activeTab` gesture permission; this test used DOM snapshots and clicking, not screenshot capture through the agent.
- Tests ran against a local nonproduction proof page at `http://127.0.0.1:8999/`; no production site modified.
- `--yes` was used only for the isolated test page to avoid an interactive approval prompt. Default approval policy remains unchanged.
- No merge to `master`, VPS deploy, or marketplace publication was performed.

**Conclusion:** The previously outstanding real-model / panel-closed CLI E2E acceptance criterion is **met** and repeatable in these two runs. It does **not** imply general production release readiness.
