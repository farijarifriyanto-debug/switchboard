# Switchboard Cloud Standalone — implementation and release gate

Date: 2026-10-29. Owner specification: install the Chrome extension, enter a BotConnector API key, and immediately use BotConnector AI Cloud and browser agent without installing/running Switchboard CLI or `sbx web`.

Status: **implementation and bounded real Chrome/provider E2E PASS; 0.4.8 release candidate only. No store publication**.

## Implementation

- `browser-extension/cloud-agent.js` reuses the authenticated BotConnector `GET /v1/models` catalog schema (also used by BCCLI), filters to models explicitly declaring `botconnector_capabilities.tools === 'supported'`, and exposes real `botconnector_name`, family, Free/Paket access and context metadata. The side panel provides search, Free/Paket filter, refresh and a quick model chooser in the composer; switching models persists the choice without re-entering the key and resets chat memory. An advertised model is not a guarantee of account entitlement. It uses a fixed HTTPS origin and OpenAI-compatible chat/completions tools API. It never calls local Switchboard, native messaging, or a Web Console. Agent conversation is memory-only in the panel, capped at eight model rounds. For explicit page-summary/read/click instructions, the extension obtains a deterministic real DOM snapshot **before** the first model request, then passes it as bounded, untrusted tool messages; model discretion alone cannot bypass this evidence step.
- Side-panel BotConnector BYOK form saves model and API key in extension-local storage with access restricted to trusted extension contexts; no Chrome sync, no webpage scripts and no audit logs. The key can be deleted in the same panel. Unlike the older local-BYOK path, no independent Web Console approval is needed; user-entered key resides in the extension at rest.
- The existing service-worker browser tool executor, native Chrome per-site host permission, sensitive field blocking, tab binding and audit behavior remain in charge of browser actions. **User-managed Cloud tab attachment** uses a session-only list of up to 12 explicit HTTP(S) attachments, one selected target, and controls to attach from open tabs, select/switch, and detach without closing the Chrome tab. Cloud browser execution verifies the selected tab ID at every tool call and never falls back to another active tab. Cloud `browser_tabs_list` only returns already attached tabs; model-initiated tab selection is removed. Code review follow-ups: token-aware page intent prevents unrelated webpage snapshots, a post-approval abort prevents stale clicks, and full text/URLs must be visible to the confirmer (long proposed writes and URLs are rejected). Cloud can be disabled with the existing active-model checkbox without deleting its key, and activating an optional local provider disables Cloud. Cloud writes/navigation require explicit action confirmation; clicks verify the real visible element label against a fresh DOM snapshot before approval. Failed or rejected mutations never retry.
- Chrome permission adds **only** `https://api.botconnector.id/*` as the fixed Cloud endpoint; arbitrary user-provided cloud URLs are prohibited.
- Mode local/other providers remains optional; the published 0.4.7 package is unaffected. Standalone mode currently supports BotConnector only and a restricted browser tool subset, not a full cloud-remote task scheduler.

## Chat copy acceptance (0.4.8 test extension)

- Every user question and AI message (both Cloud and optional local backend) exposes an **icon-only Copy button**. User-copy sends only the original user question; reply-copy sends only the AI answer. Accessible labels and tooltips distinguish the targets. The header Copy icon exports the current user/AI transcript, not browser tool outputs, errors or API keys. Original raw answer text is used rather than DOM-derived HTML. Neither operation saves a transcript to disk or extension storage.
- Disposable real Chrome QA validates both buttons, clipboard text contents (intercepted clipboard write to avoid mutating operator clipboard), absence of API key/HTML, SVG icon preservation, and New Chat clearing and disabling copy until the next response. This test checks the user action and payload; ordinary OS clipboard write requires a user gesture and browser permissions.

## Mandatory limitations / publication controls

- **Secrets:** Extension-local storage is not an independently encrypted key vault; do not use shared/untrusted devices. No claim of zero data leaving the laptop: user prompts and approved website content travel to BotConnector. Chrome Web Store privacy declarations must be updated to match.
- **Model access:** The user must have a valid BotConnector API key and a model that supports tool calls; invalid keys (401/403) or throttling (429) fail transparently without hidden fallback to a local server.
- **Background execution:** Closing the side panel ends its in-memory Cloud agent run. No promised unattended/cloud scheduling.
- **Release:** Version 0.4.7 was already submitted per owner and does NOT include standalone. **0.4.8 is not submitted or live**. Do not tag, publish npm or update Chrome Web Store until independent release authorization and publisher privacy/permission review.
